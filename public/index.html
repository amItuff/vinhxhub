04 / TRANSPARENCY & SAFETY

Câu hỏi & Bằng chứng An toàn

Tất cả cơ chế xử lý token, lưu trữ phiên và giới hạn tốc độ đều minh bạch dựa trên mã nguồn thực tế.

01

Token có bị lưu vào ổ đĩa hay cơ sở dữ liệu không?

Không. Backend lưu phiên làm việc bằng cấu trúc Map tạm thời trong RAM (const sessions = new Map()). Không có file log, database hay dịch vụ bên thứ ba nào nhận hoặc lưu trữ token của bạn.

server.js → const sessions = new Map() // In-memory ephemeral sessions
02

Trình duyệt lưu gì khi giữ phiên sau khi F5?

Trình duyệt chỉ lưu duy nhất mã phiên ngẫu nhiên UUID (vinhxhub_session_id) trong localStorage. Discord Token gốc không bao giờ được lưu trong localStorage, cookie hay DOM.

app.js → localStorage.setItem('vinhxhub_session_id', id)
03

Khi bấm Thoát hoặc không dùng nữa thì sao?

Khi bấm Thoát (/api/auth/logout), server lập tức hủy mọi tác vụ đang chạy qua AbortController, đóng luồng SSE và xóa sạch phiên khỏi RAM. Ngoài ra, phiên không hoạt động tự động bị xóa sau 6 giờ.

server.js → sessions.delete(req.sessionId) & 6h TTL cleanup
04

Cơ chế chống Rate Limit và bảo vệ tài khoản?

Quest Runner dùng cấu hình Parallel Safe Turbo: tự đọc retry_after khi gặp HTTP 429, thêm độ trễ ngẫu nhiên (jitter ±1.5s) cho mỗi heartbeat 16.5s và cho phép dừng khẩn cấp bất cứ lúc nào.

server.js → heartbeatIntervalMs: 16500, heartbeatJitterMs: 1500, HTTP 429 backoff
05

Web kết nối tới những máy chủ nào?

Chỉ gọi trực tiếp API chính thức của Discord (discord.com/api/v9), danh sách game công khai từ Discord CDN (cdn.discordapp.com/detectables/games.json) và thông số client windows từ cordapi.dolfi.es (có fallback tĩnh).

discord.com/api/v9 · cdn.discordapp.com · cordapi.dolfi.es
06

Các lớp bảo vệ HTTP trên server là gì?

Express bật sẵn header chống nhúng iframe (X-Frame-Options: DENY), chống đoán MIME (X-Content-Type-Options: nosniff), giới hạn Referrer-Policy và giới hạn payload JSON tối đa 128KB.

X-Frame-Options: DENY · nosniff · express.json({ limit: '128kb' })
